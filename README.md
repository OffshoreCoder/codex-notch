# Codex Notch

Маленький робот в чёрной области у выреза Mac показывает события локального Codex. Собственная утилита на Swift/AppKit: без зависимостей, API-ключей, скачивания пакетов и установки в Applications. Программа собирается локально из исходников.

## Запуск

1. Откройте `run.command`. Если готовой сборки нет, он соберёт приложение штатным Swift-компилятором (нужны уже установленные Apple Command Line Tools). Запуск выполняется с системным запретом сетевых вызовов. Не требует `sudo` и ничего не добавляет в автозагрузку.
2. Для подключения к Codex откройте `connect.command`. Он добавит свои обработчики в `~/.codex/hooks.json`, сохранив существующие. Перед изменением создаётся точная резервная копия рядом с файлом.
3. В терминале запустите `codex`, откройте `/hooks`, проверьте новые обработчики и доверьте им выполнение. Откройте новый чат в приложении, чтобы настройки точно загрузились. Codex требует этот шаг для пользовательских hooks: программа не меняет записи доверия. Этот интерфейс документирован для Codex CLI; интерфейс настроек hooks в desktop здесь не проверялся.

В обычном состоянии робот встроен в чёрное продолжение выреза справа: ширина 32 пункта, высота равна верхней полосе экрана. Сама фигурка высотой около 24 пунктов находится внутри этой полосы, над рабочими окнами. Физическая область камеры не содержит доступных для рисования пикселей, поэтому программа использует соседнюю область дисплея. На заполненной строке меню это место может пересекаться с ближайшим системным значком; персонажа можно скрыть через его меню и пользоваться штатным значком программы.

Работа, редактирование и проверка действия меняют только выражение робота и цвет значка. Карточка раскрывается под вырезом на 8 секунд при завершении, на 4 секунды при остановке. Наведение на 0,5 секунды или нажатие на робота показывает состояние; нажатие на робота или раскрытую карточку открывает пульт чатов.

На внешнем экране или Mac без выреза обычного плавающего окна нет: остаётся только штатный значок в строке меню. Карточка появляется временно при уведомлении или через пункт «Показать состояние». В меню также можно выбрать экран, скрыть персонажа, посмотреть демонстрацию и завершить программу.

`run.command --demo coding` показывает демонстрацию без изменения настроек Codex. Доступны также `idle`, `working`, `checking`, `finished`, `interrupted`, `unknown`, `needsAnswer`, `needsReview`. Для возврата к реальным событиям используйте меню робота.

## Приватность

- Нет серверов, аналитики, телеметрии, обновлятора или сетевого клиента. Используются только системные библиотеки Apple. Графика нарисована программно.
- Обработчик получает JSON события Codex и сразу отбрасывает текст запроса, команды, содержимое файлов, результаты инструментов и путь к переписке.
- На диске остаются типы событий, идентификаторы, имена инструментов и время. `library.json` дополнительно хранит очередь, введённые вручную подписи чатов, выбор уведомлений, тихий режим, таймеры и явные просьбы внимания. Они нужны для различения нескольких чатов и перехода к нужному чату.
- События находятся в `.codex-notch-runtime` рядом с `.app`. Права папки — `0700`, файлов — `0600`. Приложение удаляет прочитанные события; при выключенном приложении очередь ограничена последними 256 событиями. Настройки Codex сохраняются с правами только владельца.
- Не нужны Accessibility, запись экрана, доступ к контактам, ключам или текстам переписки. Персонаж не перехватывает фокус клавиатуры. Пульт получает фокус только при ручном открытии.
- `run.command` дополнительно применяет штатный профиль `offline.sb`, запрещающий сетевые системные вызовы. При непосредственном запуске `.app` этот профиль не применяется; сетевого кода в программе всё равно нет. Обработчики hooks запускают отдельный короткий процесс той же программы, который только сохраняет короткое событие без текста переписки и команд.

## Что означают состояния

| Состояние | Источник |
| --- | --- |
| Готов к работе | Открыта локальная сессия, активного хода ещё нет |
| Разбирается в задаче | `UserPromptSubmit` или работа инструмента |
| Пишет код | Выполняется `apply_patch`, `Edit` или `Write` |
| Проверка действия | `PermissionRequest`, без автоматического раскрытия карточки |
| Готово | `Stop` основного хода |
| Остановлен | `Interrupt` |
| Нет свежих событий | 30 минут не поступали сигналы |

«Пишет код» означает наблюдаемое редактирование файлов. Быстрые правки подсвечиваются в течение 1,25 секунды после события, если ход ещё продолжается. Команды Bash не анализируются: изменение файлов через shell может отображаться как обычная работа.

`PermissionRequest` срабатывает **перед** решением об одобрении; другой обработчик, политика или Auto-review могут разрешить действие без участия человека. Этот hook не подтверждает, что диалог разрешения действительно показан. Поэтому робот показывает нейтральное состояние «Проверка действия» и **никогда не раскрывает карточку автоматически** по этому событию. Даже задержка перед показом не решает проблему: уже разрешённая команда может выполняться долго.

У hooks нет отдельного события завершения одобрения, поэтому нейтральная подпись может оставаться до результата инструмента. Для параллельных вызовов одного инструмента она сохраняется, пока все известные вызовы этого типа не завершатся. Оповещения «Нужен твой ответ» и «Просит посмотреть результат» используют отдельный явный маркер, описанный ниже. Они не означают запрос разрешения безопасности. Она не принимает решений о разрешениях.

Программа наблюдает локальные hooks. Облачные выполнения и инструменты без локальных hook-событий не видны. Если корпоративная политика отключает пользовательские hooks, программа не обходит её. Формат транскриптов не используется.

## Отключение

Завершите программу через её меню и запустите `disconnect.command`. Удалятся только обработчики Codex Notch; все остальные hooks сохранятся. После этого папку программы можно удалить. Никаких LaunchAgents, служб или элементов входа программа не создаёт.

Если перемещаете эту папку, повторите `connect.command`, чтобы обновить абсолютный путь обработчиков, и проверьте доверие в `/hooks`.

## Сборка и проверки

На машине с уже установленными Apple Command Line Tools:

```sh
./build.command
./test.command
```

Сборка рассчитана на macOS 13+ и текущую архитектуру Mac. Бинарники и локальные события не хранятся в Git. Подпись локальная (ad hoc), без отправки программы на сервер нотариализации.

`./CodexNotch.app/Contents/MacOS/CodexNotch --print-hooks` показывает предлагаемый результат слияния настроек без записи. `--hooks-file /path/hooks.json` позволяет проверять подключение на отдельном файле. `CODEX_NOTCH_DATA_DIR` задаёт другую папку событий для тестирования.

Проверки покрывают несколько чатов, параллельные разрешения, поздние события дочерних инструментов, устаревшие сигналы, удаление приватных полей, права/границы очереди и безопасное слияние/удаление hooks. Вызовы hooks всегда возвращают `{}` и код `0`, даже если персонаж недоступен; они не принимают решений о разрешениях.

Официальный контракт интеграции: [Codex Hooks](https://learn.chatgpt.com/docs/hooks).

## Непросмотренные результаты

Каждый завершённый ход попадает в локальную очередь отдельно от состояния других чатов.
На роботе остаётся точка, у значка меню — число результатов. Меню «Ожидают просмотра»
открывает конкретный чат и отмечает выбранный результат просмотренным; можно очистить
всю очередь явно. Открытие Codex другим способом ничего не отмечает автоматически.
Очередь переживает перезапуск. Повторный `Stop` не добавляет уже просмотренный ход.
Хранятся до 512 результатов и 4096 ключей дедупликации; при переполнении удаляются старейшие.
`Stop` означает окончание хода, а не успешность всей задачи.

## Пульт чатов

Нажатие на робота или «Чаты и результаты…» открывает пульт под вырезом: каждый известный чат,
состояние, время хода и давность сигнала. «…» → «Переименовать на этом Mac…» задаёт подпись только на этом Mac.
«Открыть чат» переходит по его UUID и отмечает результаты этого чата просмотренными.
«Просмотрено» позволяет сделать это без перехода. После перезапуска старый работающий чат
показывается как последнее известное состояние до нового события; работа не выдумывается.
Хранятся метаданные до 256 последних чатов и локальные подписи (до 80 символов). Имена из Codex подхватываются автоматически, ручные подписи имеют приоритет.

## Уведомлять об одном чате

В пульте у чата откройте «…» → «Уведомлять об этом чате». Автоматические карточки завершения и остановки
будут появляться только для него. Остальные результаты по-прежнему сохраняются в очереди
и видны в счётчике. Снимите выбор той же кнопкой, чтобы снова получать сигналы всех чатов.
Выбор сохраняется локально между запусками.

## Тихий режим

В пульте «Не отвлекать» включает тишину на 25/30 минут, час или до ручного выключения.
Автоматические карточки не раскрываются, результаты продолжают копиться. После окончания —
одна карточка с числом непросмотренных результатов, пришедших за это время. Уже просмотренное
и результаты других чатов при выбранном важном чате повторно не отвлекают. Режим переживает
перезапуск; истёкший таймер обрабатывается при следующем запуске. Наведение и ручной пульт доступны.

## Напоминания

У каждого чата в пульте есть «Напомнить»: вернуться к непросмотренному результату через
5/10/30 минут либо один раз сообщить, если текущий ход длится дольше 10/20/30 минут.
Порог долгого хода считается от его начала, а не от нажатия кнопки. Новое напоминание того
же типа заменяет старое; «Отменить напоминания» убирает оба. Просмотр результата отменяет
его таймер, окончание или смена хода — таймер длительности. Долгий ход не называется зависшим.
Таймеры локальные и переживают перезапуск. После перезапуска проверка длительности ждёт
свежего подтверждения того же работающего хода. Напоминания, заданные вручную, действуют
даже для невыбранного чата, соблюдают тихий режим и включаются в его единую сводку.

## Проверка подключения

Пункт меню «Проверить подключение…» показывает давность последнего реального hook-события,
проверки исполняемого файла, пути и всех восьми обработчиков в `hooks.json`, прав каталога.
Кнопка проверки записи и чтения использует отдельный временный файл, не расходует живые
события и не правит настройки. Доверие Codex к hooks здесь не проверяется: его подтверждают
`/hooks` и настоящее событие нового чата. Нет событий — неизвестность, а не доказанный сбой.
В терминале доступны `--health` и `--health --self-test` (код 1 только при обнаруженной проблеме).

## Явный запрос ответа или просмотра

Кнопка «Сигналы…» в пульте копирует инструкцию. Вставьте её в нужный чат:
агент будет отправлять точную отдельную shell-команду непосредственно перед вопросом или
просьбой посмотреть результат. Обязательной установки skill и изменения глобальных инструкций нет.

```sh
: codex-notch:question
: codex-notch:review
: codex-notch:clear
```

Это безвредные no-op команды. Обработчик `PostToolUse` распознаёт **только точное совпадение**
маркера у `Bash` (так hooks называют shell/unified exec); также поддержаны `exec_command.cmd`
и `shell_command.command`. Он сразу отбрасывает текст команды и сохраняет тип сигнала,
точные ID чата/хода из hook и время. Вложенный JavaScript, echo, составные shell-команды,
похожие строки и обычные сообщения не распознаются. Если путь выполнения не отправляет
локальные hooks, сигнал недоступен. Это явное заявление агента, а не чтение интерфейса вопроса.

`Stop` и результаты инструментов просьбу не сбрасывают. Она остаётся до «Просмотрено», открытия
чата через пульт, нового запроса пользователя, остановки/закрытия соответствующего хода или
маркера `clear`. Старые и несовпадающие ходы игнорируются, повторы не всплывают. Тихий режим
и выбор важного чата применяются к этим сигналам; отметка внимания остаётся в пульте.
Для собственной интеграции: `--attention question|review|clear --session UUID --turn TURN_ID`.
Нужен точный ID известного текущего хода; команда не угадывает последний чат.

`PermissionRequest` по-прежнему означает только «Проверка действия» и никогда автоматически
не раскрывает карточку. Никаких решений об одобрении программа не принимает.

Проверки включают 110 сценариев явных сигналов, 83 сценария настройки hooks, 45 сценариев
диагностики, а также модель состояний, очередь, приватность, хранение, таймеры и тихий режим.
`--preview PATH --preview-dashboard` отрисовывает пульт с демонстрационными данными, не читая
живую очередь. Результаты и явные просьбы внимания ограничены 512 записями каждого типа.

## Компактный пульт под вырезом

Левый клик по роботу или значку меню открывает тёмную панель под вырезом экрана.
На внешнем мониторе и Mac без выреза она появляется под значком в строке меню.
Панель шириной 520 пунктов показывает сводку «В работе / Ждут тебя / Готовы»,
фильтры чатов и действия «Открыть», «Просмотрено», «Напомнить».
Переименование и выбор важного чата находятся в меню «…» у строки.
Esc, повторный клик по роботу или клик снаружи закрывают панель. Для закрытия отслеживаются
только события нажатия мыши, без Accessibility, чтения клавиатуры и сохранения событий.
«Открыть» выделено синей кнопкой. После успешного перехода в чат пульт закрывается.
Пульт никогда не раскрывается сам. Правый клик/control-click по значку открывает настройки,
диагностику подключения и выбор экрана. Маленькие уведомления завершения сохраняют прежнее поведение.

## Автоматические имена чатов

Пульт и очередь показывают имена из локальных метаданных Codex. Ручная подпись в «…»
имеет приоритет; очистите её, чтобы снова видеть имя Codex. Источник обновляется в фоне
примерно раз в 5 секунд. При временной ошибке остаются последние считанные имена. Импортированные имена остаются только в памяти; после перезапуска
читаются заново. Если имя отсутствует, показывается «Чат без названия», короткий ID остаётся
второстепенной подсказкой.

Используется системная SQLite Apple: только `threads.id` и `threads.name` для ID уже известных
чатов. База открывается только для чтения; чаты и настройки Codex не изменяются. Поля
`title`, `preview`, `first_user_message`, JSONL и переписка не читаются. Никаких сетевых запросов.
Схема локальной базы не является стабильным публичным API: при несовместимости или отсутствии
источника сохраняется ручная подпись/заглушка, причина видна в диагностике подключения.
Поиск: `state_<номер>.sqlite` в `CODEX_SQLITE_HOME`, `CODEX_HOME` или `~/.codex`.
Для нестандартного расположения можно задать `CODEX_NOTCH_STATE_DB` с точным путём к базе.

## Пульт с клавиатуры

`⌃⌥Пробел` (Control + Option + Space) открывает пульт под вырезом и сразу ставит курсор
в поиск по названиям чатов. Введи часть названия, выбери чат стрелками ↑ / ↓ и нажми Enter.
Esc закрывает пульт. Поиск работает локально, без сохранения поисковых запросов.

Внизу пульта кнопка сочетания позволяет выбрать готовый вариант, записать собственное
сочетание с Control, Option или Command либо выключить горячую клавишу. Если сочетание
уже занято, программа сообщает об этом и сохраняет прежнее. Используется системная
регистрация Carbon `RegisterEventHotKey`; перехвата всех клавиш и разрешения Accessibility нет.

## Проект и рабочая копия

Под названием чата пульт показывает проект, текущую Git-ветку и имя связанной рабочей копии.
Источник — `cwd` локального hook и только `.git`, `HEAD`, `commondir`, `gitdir`.
Код, Git-конфигурация, remotes и история коммитов не читаются, команды Git не запускаются.
Контекст обновляется в фоне раз в 5 секунд. Путь сохраняется локально, полный путь доступен
в подсказке. Пока новый hook не передал каталог, пульт прямо пишет, что контекста ещё нет.

## Локальные результаты и проверки

«Сигналы…» копирует также инструкцию для передачи результата. Агент выполняет точную
no-op команду `: codex-notch:result BASE64`, где BASE64 содержит UTF-8 JSON с полем
`checks` (`passed`, `failed`, `notRun`) и необязательным `path` существующего локального
документа. Например, JSON `{"checks":"notRun"}` сообщает, что проверки не запускались.
Произвольные сообщения, команды и вывод инструментов не анализируются.
Пульт честно подписывает источник: «Агент сообщил: проверки пройдены».
«Результат» открывает прикреплённый файл стандартным приложением macOS. Путь проверяется
повторно при нажатии. Приложения, скрипты, пакеты и ссылки не принимаются.
Сигнал применяется только к совпадающему известному ходу. `Stop` не создаёт итог проверок.

## Открыто и проверено

Открытие чата/файла с явной просьбой review или приложенным результатом переводит его
в «На проверке». Очередь и напоминания сохраняются. Кнопка «Проверено» явно завершает
проверку. Обычные завершения без такой просьбы по-прежнему снимаются при открытии.
Это локальная отметка пользователя, она не отправляет сообщение агенту и не меняет Codex.

## Уведомления с учётом работы

Короткий обычный ход обновляет очередь без карточки. Карточка обычного завершения появляется,
если известная длительность хода не меньше минуты и Codex сейчас не на переднем плане.
Явные вопросы и просьбы проверить результат сохраняют приоритет. После сна, возвращения
в пользовательскую сессию или чтения накопленной очереди появляется одна сводка вместо
серии карточек. Ручные напоминания и «Не отвлекать» продолжают действовать.
